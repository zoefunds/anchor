# @anchor/solana-escrow-client

Checked-in, generated Anchor IDL + typed client for
`chains/solana/programs/escrow` (the reference Sealevel escrow program —
NOT `decision-relay`, which is a native, non-Anchor program with no IDL;
see its own `lib.rs` header for why).

## Contents

- `idl/escrow.json` — the real IDL, generated by `anchor build -p escrow`
  from `chains/solana/programs/escrow/src/lib.rs` and copied verbatim
  from `chains/solana/target/idl/escrow.json` (gitignored build output,
  regenerated on every `anchor build`; this copy is the durable,
  reviewable one).
- `idl/escrow.ts` — the matching TS type helper Anchor generates
  alongside the IDL (`chains/solana/target/types/escrow.ts`), giving
  `Program<Escrow>` full method/account/type inference.
- `index.ts` — a small typed wrapper (`getEscrowProgram`,
  `deriveCasePda`, `buildInitializeCaseInstruction`) so callers never
  hand-encode instruction discriminators or Borsh args themselves.

## Regenerating

```
cd chains/solana
anchor build -p escrow
cp target/idl/escrow.json ../../packages/solana-escrow-client/idl/escrow.json
cp target/types/escrow.ts ../../packages/solana-escrow-client/idl/escrow.ts
```

Do this any time `programs/escrow/src/lib.rs` changes, in the same
commit as the source change. `.github/workflows/solana-idl-consistency.yml`
fails CI if the checked-in copies ever drift from a fresh build of the
current source.

## Test-only vs. real

This package holds only the plain (non-`test-attestors`) build of
`escrow` — the program itself has no test/prod feature split (that only
exists on `decision-relay`, which has no IDL at all). The `address`
field inside `idl/escrow.json` is the program ID declared in
`programs/escrow/src/lib.rs`'s `declare_id!` and is the same for
devnet/localnet source; the actual deployed program id per cluster
still comes from `chains/solana/Anchor.toml` / env config, not from
this file — do not assume the IDL's `address` is authoritative for
"which deployment to talk to."
