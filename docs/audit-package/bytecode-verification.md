# Bytecode & compiler verification

## Compiler

All Solidity contracts (`chains/evm/contracts/*.sol`) declare
`pragma solidity ^0.8.24;`. `chains/evm/foundry.toml` does **not** pin an
exact `solc_version` or `evm_version` — it uses Foundry's default
resolution for whatever's installed/cached locally at build/deploy time.
This is a real gap: **the exact compiler version and optimizer settings
used for the currently-deployed bytecode are not currently pinned or
recorded anywhere in this repo.** An external reviewer cannot reproduce
the exact build from the source tree alone today. Closing this means
adding an explicit `solc_version = "0.8.24"` (or whatever exact patch
version was actually used) plus `optimizer`/`optimizer_runs` values to
`foundry.toml`, and recording them at deploy time.

## Deployed bytecode hashes

`apps/web/deployment-manifest.json` and
`apps/web/deployment-manifest.solana.json` (regenerated by
`scripts/generate-deployment-manifest.ts`, live on-chain reads, not
inferred) record a `codehash` field per contract — e.g.
`decisionRelay.codehash` in the EVM manifest. These are the actual
`keccak256` of the deployed runtime bytecode read directly from Sepolia
at manifest-generation time. Anyone can independently recompute this by
calling `eth_getCode` on the recorded address and hashing the result —
that's exactly what `generate-deployment-manifest.ts` does; nothing here
is asserted without a corresponding on-chain read.

**What this does NOT establish**: a matching codehash between two
manifest snapshots proves the contract hasn't been redeployed/changed
between those two reads. It does **not**, by itself, prove the deployed
bytecode was compiled from the exact source in this repo — that
requires either (a) public source verification (see below, not done
yet) or (b) an independent reviewer compiling the source themselves
with the pinned compiler settings above (also not pinned yet) and
comparing bytecode by hand.

## Public source verification

**Not currently done.** No Etherscan/Sourcify verification step exists
in this repo — no API key configuration, no `forge verify-contract`
invocation in any deploy script under `chains/evm/deploy/`, and no
recorded verification link in any deployment-manifest doc. This is a
real, open gap, not a resolved item:

- Etherscan (Sepolia): not verified. No public "Contract" tab exists for
  any of the addresses in `deployment-manifest.json` as of this
  package's writing, as far as this repo's own artifacts can attest —
  an external reviewer should check the addresses directly
  (`https://sepolia.etherscan.io/address/<address>#code`) rather than
  trust this document's absence-of-evidence.
- Sourcify: not submitted.

Closing this gap requires running `forge verify-contract` (or the
Sourcify equivalent) against each deployed address once the exact
compiler/optimizer settings above are pinned and confirmed to match
what was actually used at deploy time — verifying against the wrong
settings will simply fail, which is itself useful confirmation that the
pinned settings are correct.
