# Topology — attestor / Safe / ISM / mailbox / escrow / relay

This document links to and summarizes the real, on-chain-read sources of
truth rather than re-deriving topology facts by hand — every number
below should be cross-checked against the cited manifest/source file,
which is regenerated from live chain reads.

## Sources of truth

- `apps/web/deployment-manifest.json` — EVM side: DecisionRelay, Safe,
  ISM, attestor set, codehash. Regenerated by
  `scripts/generate-deployment-manifest.ts`.
- `apps/web/deployment-manifest.solana.json` — Solana side: escrow
  program, PDAs, addresses.
- `apps/web/src/lib/reliability-monitor.ts` — the `VALIDATORS` and
  contract-address constants at the top of that file are the current
  Hyperlane mailbox/ISM/validator-announce/decision-relay/trusted-sender
  addresses actually being read against in the reliability sweep; kept
  in sync with `chains/hyperlane-validator/deployment.json` per that
  file's own comments.
- `docs/multisig-attestor-setup.md` — attestor role setup and signer
  independence status.
- `docs/hyperlane-integration.md` — the mailbox/ISM/relay wiring
  narrative.

## Summary (as of the manifests cited above — always re-check the live JSON)

- **DecisionRelay** (EVM settlement contract): owned by a 2-of-2 Safe.
  `deployment-manifest.json`'s own `flags` field already states the real
  risk here explicitly: *"Safe is 2-of-2 with only 2 owners — no
  redundancy if either owner's key is lost; operator independence
  between these two owners is UNVERIFIED."* This package does not
  soften that language.
- **Attestors**: DecisionRelay's active attestor set and threshold are
  read live via `isAttestor()` calls, not an enumerable getter — see
  the manifest's own `attestors.note` for that exact limitation
  (an attestor added/removed outside the script's known candidate list
  would not show up).
- **ISM / mailbox / validators**: see `reliability-monitor.ts`'s
  `VALIDATORS` array for the current 3-validator set and each
  validator's operator/account/cloud-provider — `checkValidatorIndependence`
  in that file is the live, automated check for whether they actually
  share infrastructure (shared infrastructure would compromise the
  quorum's independence guarantee).
- **Escrow**: two ABI versions are tracked
  (`EscrowVersion.V1`/`V2` in `apps/web/prisma/schema.prisma`) —
  `ESCROW_VERSION_MISMATCH` reconciliation findings exist specifically
  to catch a redeploy-at-the-same-address attack against whichever
  version is actually live; see `docs/v1-v2-escrow-cutover.md`.
- **Relay**: `packages/hyperlane-relay` — the off-chain component that
  submits signed decisions to Hyperlane's mailbox for cross-chain
  delivery; its own message-body encoding is duplicated (deliberately,
  see that module's own comments) in `reliability-monitor.ts` for
  wiring verification without a full build dependency.

## What is NOT independently attestable from this package alone

- Whether the Safe's two owner keys are actually held by two distinct,
  non-colluding parties — this is an operational/organizational fact,
  not something derivable from chain state. See `known-limitations.md`.
- Whether the RPC endpoints used to read the manifests above were
  themselves honest (a malicious or compromised RPC provider could, in
  principle, lie about `eth_getCode`/`eth_call` results). No independent
  multi-provider cross-check is currently performed — a real gap, listed
  in `known-limitations.md`.
