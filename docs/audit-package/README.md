# External audit package — entry point

Anchor is **testnet-only**. Nothing in this package, or anywhere it
links to, is a claim that the system is ready for mainnet deployment or
real customer funds. See `docs/mainnet-readiness-gate.md` for the actual
gate that has to be cleared before that changes.

This package exists so an external reviewer — an auditor, a partner's
security team, a regulator's technical staff — can reproduce deployment
identity and evaluate known risks **without relying on chat history or
this project's own narrative**. Every claim below either cites a
specific, checked-in artifact or is explicitly marked as an open gap.
Nothing here re-derives facts already captured elsewhere; each section
links to the source of truth instead of restating it and risking drift.

## The 30-day reliability observation window

See [`../reliability-observation-window.md`](../reliability-observation-window.md)
for the written pass/fail and window-extension/reset rule, defined
**before** the observation window began. `GET /api/reliability-window`
(and the summary on the public `/status` page) is the live, queryable
view over the `ReliabilityWindowObservation` table that rule is scored
against.

**Honest status as of this package's writing:** the observation script
(`apps/web/scripts/reliability-observation.ts`) and its scheduler
(`apps/web/scripts/reliability-observation-loop.ts` /
`fly.reliability-observer.toml`) exist and have been validated logically
(see `test-evidence.md`), but the scheduler app has **not** been
deployed from this environment — there is no Fly CLI/deploy access here.
Until an operator runs `fly deploy -c fly.reliability-observer.toml`,
the 30-day clock is not accumulating real ticks. Check
`GET /api/reliability-window`'s `totalObservations` and
`lastObservationAt` fields directly — do not take this document's word
for whether the window has meaningfully started by the time you read it.

## Environment registry / manifests

- `apps/web/src/lib/environment-registry.ts` — the checked-in registry
  of every environment this deployment can run against (Sepolia
  testnet, Solana devnet/testnet, GenLayer Studio chain 61997) and the
  guard that refuses to run against an unlisted one. This package's
  claims are all scoped to whatever that registry currently lists as
  active — check it directly rather than trusting a possibly-stale list
  copied into this document.
- `apps/web/deployment-manifest.json` / `apps/web/deployment-manifest.solana.json`
  — real, live on-chain-read snapshots (owner, attestor set, ISM,
  addresses), regenerated by `scripts/generate-deployment-manifest.ts`.
  `topology.md` cites these directly rather than re-deriving them.
